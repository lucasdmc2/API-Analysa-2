🩺 API de Extração e Normalização de Exames Clínicos

✅ API ATIVA - Rodando em http://localhost:8000

📋 Visão Geral

API determinística para ingestão de laudos de exames (PDF/imagem), extração OCR, normalização LOINC/UCUM, cálculo de flags e geração de recomendações informativas para o contexto brasileiro.

🎯 Características Principais

  • Determinismo: Mesmo input → mesmo output (cache por hash)
  • Auditabilidade: Trilha completa de processamento
  • Interoperabilidade: LOINC, UCUM, SNOMED CT
  • Conformidade LGPD: Dados em território brasileiro

🔐 Autenticação

A API usa tokens Bearer para autenticação. Use um dos tokens de desenvolvimento:

Token Escopo Descrição
dev-admin read, write, admin Acesso administrativo completo
dev-user read, write Usuário regular
dev-read read Somente leitura

🔗 Endpoints Principais

GET Health Check

GET http://localhost:8000/health

Descrição: Verificação de saúde da API

Autenticação: Não requerida

Exemplo de uso:

curl http://localhost:8000/health

Resposta de exemplo:

{ "status": "healthy", "timestamp": "2025-08-27T19:30:28.892207", "version": "1.0.0-demo", "dependencies": { "database": "mock", "storage": "mock", "ocr_service": "mock" } }

POST Criar Ingestão

POST http://localhost:8000/v1/ingestions

Descrição: Criar nova ingestão de documento médico

Autenticação: Bearer token com escopo 'write'

Exemplo de uso:

curl -X POST "http://localhost:8000/v1/ingestions" \ -H "Authorization: Bearer dev-user" \ -H "Content-Type: application/json" \ -d '{ "document_type": "laboratory_report", "filename": "laudo_hemograma.pdf", "patient_id": "123e4567-e89b-12d3-a456-426614174000" }'

Resposta de exemplo:

{ "ingestion_id": "da2e9236-0044-4ee8-b9a3-969b6b570291", "status": "processing", "created_at": "2025-08-27T19:30:00.000000", "upload_url": null }

GET Status da Ingestão

GET http://localhost:8000/v1/ingestions/{ingestion_id}

Descrição: Consultar status e progresso da ingestão

Autenticação: Bearer token com escopo 'read'

Exemplo de uso:

curl -H "Authorization: Bearer dev-user" \ "http://localhost:8000/v1/ingestions/da2e9236-0044-4ee8-b9a3-969b6b570291"

GET Observações do Paciente

GET http://localhost:8000/v1/patients/{patient_id}/observations

Descrição: Listar observações laboratoriais do paciente

Autenticação: Bearer token com escopo 'read'

Exemplo de uso:

curl -H "Authorization: Bearer dev-user" \ "http://localhost:8000/v1/patients/123e4567-e89b-12d3-a456-426614174000/observations"

Resposta de exemplo:

{ "data": [ { "observation_id": "469f02b7-ec8e-4362-b3d8-ad340db8ed1a", "loinc_code": "718-7", "display": "Hemoglobina", "value_numeric": 13.2, "unit_ucum": "g/dL", "flag": "N", "collected_at": "2025-08-27T19:30:00.000000" }, { "observation_id": "547f22e9-a6de-4330-9c82-d6dea6c063a6", "loinc_code": "2345-7", "display": "Glicose", "value_numeric": 105.0, "unit_ucum": "mg/dL", "flag": "H", "collected_at": "2025-08-27T19:30:00.000000" } ], "pagination": { "has_next": false, "limit": 20 } }

POST Criar Faixa de Referência

POST http://localhost:8000/v1/admin/rangesets

Descrição: Configurar nova faixa de referência (Admin apenas)

Autenticação: Bearer token com escopo 'admin'

Exemplo de uso:

curl -X POST "http://localhost:8000/v1/admin/rangesets" \ -H "Authorization: Bearer dev-admin" \ -H "Content-Type: application/json" \ -d '{ "analyte_key": "glucose_fasting", "unit_ucum": "mg/dL", "ref_low": 70, "ref_high": 99, "confidence_level": "high" }'

⚠️ Códigos de Erro

Código Erro Descrição

404 Not Found Recurso não encontrado
422 Validation Error Dados de entrada inválidos

🔧 Teste Rápido

Como testar a API:

  1. Teste o health check: curl http://localhost:8000/health
  2. Crie uma ingestão com o token dev-user
  3. Consulte as observações do paciente demo
  4. Configure faixas de referência com o token dev-admin
